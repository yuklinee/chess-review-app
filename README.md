# Chess Review

Веб-приложение для просмотра и разбора партий Chess.com: поиск игрока, последние партии из актуального архива, интерактивная доска и полноценный анализ ходов однопоточным Stockfish WASM.

## Возможности

- Поиск игрока по никнейму через публичный API Chess.com.
- Профиль игрока: аватар, титул, рейтинги в пуле, блице, рапиде и по дням.
- Последние 10 партий из актуального архива: соперники, рейтинги, результат, контроль времени, точность, дебют и ссылка на Chess.com.
- Экран разбора: доска, SAN-нотация, ходы, кнопки «в начало / назад / вперёд / в конец», ползунок и переворот доски.
- Автоматический анализ всей партии Stockfish в фоновом Web Worker (интерфейс не блокируется).
- Бейджи классификации ходов: блестящий `!!`, лучший `★`, отличный `!`, неточность `?!`, ошибка `?`, зевок `??`.
- Бейдж оценки последнего сыгранного хода прямо над фигурой на доске.
- Точность (Accuracy %) и примерный перформанс-рейтинг для обоих игроков.
- Кнопка «Показать лучший ход»: отматывает позицию на один ход назад и показывает, что стоило сыграть вместо последнего хода; оценка в пешках или мат в N ходов и SVG-стрелка (с учётом переворота). В начальной позиции анализирует текущую сторону.
- Режим анализа: можно сыграть альтернативный ход прямо на доске; основная линия партии сохраняется.
- Навигация с клавиатуры: `←` / `→`, `Home` / `End`.
- Адаптивная тёмная тема в духе Chess.com (`#262421`).

## Стек

React 19, TypeScript, Vite, [chess.js](https://github.com/jhlywa/chess.js), [Stockfish.js 19](https://github.com/nmrugg/stockfish.js) (single-threaded lite WASM), lucide-react. Стили — обычный CSS без UI-фреймворков.

## Stockfish WASM

Движок лежит в `public/engine` и не требует npm-пакета:

- `stockfish-19-lite-single.js` — single-threaded lite-сборка Stockfish.js 19;
- `stockfish-19-lite-single.wasm` — её WASM-бинарник;
- `Copying.txt` — лицензия GPL-3.0.

Путь к worker-скрипту строится в `src/lib/stockfish.ts`:

```ts
`${import.meta.env.BASE_URL}engine/stockfish-19-lite-single.js`
```

WASM-файл загружается по URL, который также строится от `import.meta.env.BASE_URL` и передаётся worker-скрипту через hash (Stockfish.js поддерживает такой override). Поэтому 404 не возникает ни на GitHub Pages, ни при другом base. Сборка single-threaded не использует `SharedArrayBuffer`, поэтому не нужны заголовки `COOP`/`COEP`, которые GitHub Pages всё равно не позволяет настроить. GitHub Pages отдаёт `.wasm` с `application/wasm`.

Параметры анализа в `src/lib/analysisConfig.ts`:

- полный проход: глубина до 12, не более 400 мс на позицию;
- кнопка лучшего хода: глубина до 15, не более 2,5 с.

Кнопка лучшего хода работает в контексте последнего сыгранного хода: она отматывает доску на один ход назад (к позиции, из которой был сделан ход) и просит Stockfish лучший ход именно для этой позиции. В начальной позиции отматывать нечего, поэтому анализируется текущая позиция. Движок работает в отдельном `Worker`; все запросы сериализуются, поэтому фоновая партия и интерактивный «лучший ход» не конфликтуют.

## Как считается анализ

Для каждой позиции Stockfish возвращает оценку и лучший ход. Изменение оценки в сантипешках (с точки зрения сделавшего ход) классифицируется так:

| Класс | Условие |
|---|---|
| Блестящий (`brilliant`) | лучший/почти лучший ход (потеря ≤ 10 cp), который оставляет фигуру под боем, но сохраняет явный перевес (≥ +1.0 или мат) |
| Лучший (`best`) | ход совпал с лучшим ходом движка или потеря ≤ 10 cp |
| Отличный (`great`) | потеря ≤ 40 cp |
| Неточность (`inaccuracy`) | потеря ≤ 90 cp |
| Ошибка (`mistake`) | потеря ≤ 200 cp |
| Зевок (`blunder`) | потеря > 200 cp |

«Блестящий» — эвристика, приближённая к Chess.com: движок должен считать ход лучшим (или почти лучшим), после хода соперник должен иметь законный размен, забирающий фигуру с материальной выгодой (или незащищённую фигуру), а итоговая оценка остаётся выигрышной. Пешки и короли как жертвуемые фигуры не считаются, чтобы не перегружать бейдж. Это не проприетарный алгоритм Chess.com, поэтому в спорных позициях классификация может отличаться.

Точность одного хода считается по падению вероятности победы (модель Lichess):

```text
accuracy = 103.1668 * exp(-0.04354 * Δ win%) - 3.1669
```

Итоговая точность игрока — среднее по его ходам. Перформанс-рейтинг — примерная величина:

```text
performance ≈ рейтинг соперника + 800 * (результат − 0.5) + 4 * (точность − 75)
```

Оценки ограничены диапазоном 400–3000. Это именно оценка: глубина ограничена, а один ход не заменяет полноценную Elo-статистику.

## API Chess.com

Используется публичный [Published Data API](https://www.chess.com/news/view/published-data-api):

- `GET https://api.chess.com/pub/player/{username}/games/archives` — список архивов;
- `GET https://api.chess.com/pub/player/{username}/games/{YYYY}/{MM}` — партии за месяц;
- `GET https://api.chess.com/pub/player/{username}` — профиль;
- `GET https://api.chess.com/pub/player/{username}/stats` — рейтинги.

Важно: в формулировке исходной задачи endpoint указан как `/archives`, однако у Chess.com он называется `/games/archives`; в приложении используется рабочий маршрут. Берётся последний архив; если в нём пока нет завершённых партий, приложение проверяет предыдущие месяцы. API отдаёт `Access-Control-Allow-Origin: *`, поэтому запросы идут напрямую из браузера.

## Структура

```
public/engine/         — single-threaded Stockfish WASM и лицензия
src/
  lib/chesscom.ts      — запросы к Chess.com, валидация ника, выбор архива
  lib/pgn.ts           — разбор PGN через chess.js, позиции и статусы
  lib/stockfish.ts     — UCI-обёртка над Web Worker
  lib/analysis.ts      — классификация ходов, точность, performance
  lib/analysisConfig.ts
  lib/format.ts        — форматирование дат, контроля времени, результатов
  lib/pieces.ts        — символы фигур и их названия
  hooks/usePlayerSearch.ts
  hooks/useStockfishEngine.ts
  hooks/useGameAnalysis.ts
  components/          — доска, список ходов, анализ, карточки, профиль
  pages/               — главная страница и экран партии
  App.tsx              — поиск, переходы между экранами, шапка и подвал
```
